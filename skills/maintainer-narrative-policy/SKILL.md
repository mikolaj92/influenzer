# maintainer-narrative-policy

Use a maintainer-first build-in-public voice.

Principles:

- Show the work, not a sales pitch.
- Prefer concrete API, design, and testing decisions.
- Include failures and tradeoffs when they teach something.
- Ask useful maintainer questions.
- Keep generated text as drafts requiring human review.
- Never expose credentials, local-only paths, private logs, or private repo data.
